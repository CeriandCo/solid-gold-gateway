## 1. Function EXECUTE privileges

| # | Check | Result |
| - | ----- | ------ |
| 1 | Before: `anon` and `authenticated` could EXECUTE 18 functions in `public`, including `gift_card_order_settle`, `aurum_fetcher_tick`, `aurum_backfill_tick` | CONFIRMED (the reported vulnerability was real) |
| 2 | `REVOKE ALL FROM PUBLIC, anon, authenticated` on every commerce, cron, trigger and admin-guard function; `GRANT EXECUTE` to `service_role` only | PASS |
| 3 | RLS helpers `aurum_current_editor_role`, `aurum_can_edit_draft`, `aurum_can_edit_post_sources`, `aurum_link_current_editor`: revoked from PUBLIC/anon, kept for `authenticated` | PASS |
| 4 | `aurum_replace_post_sources` is called by the admin through the user-scoped client (`src/lib/admin.functions.ts`), so `authenticated` kept, `anon` revoked | PASS |
| 5 | After: no function in `public` is executable by `anon`; only the four helpers (plus non-definer `aurum_replace_post_sources`) are executable by `authenticated` | PASS |
| 6 | `postgres` (the pg_cron job owner) retains EXECUTE on all 24 functions | PASS |
| 7 | `ALTER DEFAULT PRIVILEGES IN SCHEMA public REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC, anon, authenticated` applied for the migration owner | PASS — accepted on this platform. Caveat: default privileges bind to the role that creates the function, so a function created later by a different role can still arrive with the PUBLIC grant. That is why check 8 exists. |
| 8 | Permanent regression test `src/lib/security/function-privileges.test.ts` (3 tests) reads `pg_proc` through the new `security_function_grants()` audit function and fails on any anon-executable function, any non-allowlisted SECURITY DEFINER function executable by `authenticated`, or any function not executable by `service_role` | PASS |
| 9 | Crons still work after the change: `aurum-gold-price-fetch-5min`, `commerce-delivery-tick`, `commerce-activate-due` all `succeeded` at 13:00 and 13:05 UTC, after the migration | PASS |
| 10 | Admin CMS still works: a temporary editor signing in over HTTP gets `editor` from `aurum_link_current_editor` and can read posts; drafts/sources/people/settings all run through the same user-scoped client and the four retained helpers | PASS |

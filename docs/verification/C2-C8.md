# C-2 / C-8 verification

Date: 2026-09-21. Nothing published.

## C-2 — range buttons scrolled the page back to "Today's gold price"

### Actual cause (measured, not guessed)

The range buttons are plain `<button type="button">` elements with a React
`onClick`; they are not inside a form or anchor and the section does not remount.
Instrumenting `window.scrollTo`, `Element.scrollIntoView`, `HTMLElement.focus`
and `Element.scrollTop` showed **no application scroll call** at click time.

The jump only reproduces when the URL carries a hash. The realistic client path
is the hero CTA "See today's price ↓" (`href="#price"`) or the floating section
nav, which leaves the URL at `/aurum?range=1Y#price`. `AurumPageContent.changeRange`
then rewrote the location to record the new range. Any location change that keeps
`#price` makes TanStack Router re-apply the fragment and scroll the `#price`
section to the top of the viewport — the exact reported symptom. It fires once,
because after the first click the viewport is already at the anchor.

Published site, before the fix (Chromium, `/aurum` → click "See today's price" →
scroll to the range row → click each range):

```
1280x900  30D: before=1690 after=824   <-- jump to #price
1280x900  90D: before=824  after=824
1280x900  1Y : before=824  after=824
1280x900  5Y : before=824  after=824

390x844   30D: before=2404 after=683   <-- jump to #price
390x844   90D: before=683  after=683
390x844   1Y : before=683  after=683
390x844   5Y : before=683  after=683
```

Without a hash in the URL the same run measured `delta=0` on every click, which
is why earlier attempts looked clean.

### Fix

`src/routes/aurum.tsx` — the hand-written `window.history.replaceState` is
replaced by a router navigation that keeps the URL state and disables both scroll
behaviours:

```ts
void navigate({
  search: (prev) => ({ ...prev, range: nextRange }),
  hash: (prev) => prev,
  replace: true,
  resetScroll: false,
  hashScrollIntoView: false,
});
```

## C-2, other in-section controls (`/aurum#price`, 1280x900, fresh load each)

| Control | scrollY before | scrollY after | Assessment |
|---|---|---|---|
| Range 30D / 90D / 1Y / 5Y | 1690 | 1690 | fixed, no movement |
| Daily Note expander | 2407 | 2915 | intentional bounded nearest-edge scroll (`useNearestPanelScroll`) when the revealed panel extends below the viewport; downward only, no URL change |
| Weekly Brief expander | 3368 | 3897 | same intentional nearest-edge scroll |
| Sources toggle | 3553 | 3972 | same intentional nearest-edge scroll |
| Calculator amount input | 5998 | 5998 | no movement |
| Calculator date input | 5998 | 5998 | no movement |
| Calculator "Show the look back" submit | 5998 | 5998 | no movement |

None of these change the URL (`/aurum?range=1Y#price` throughout), so none is in
the same bug class. Opening a Weekly Brief while a Daily Note is open collapses
the note above it, which reflows the page (measured 6750 → 3897); that is the
existing exclusive-expansion behaviour, not a scroll call.

## C-8 — look-back calculator date copy

Raw query against the live price history table (`aurum_daily_closes`; there is no
`observed_at` column on it — `price_date` is the stored close date,
`aurum_spot_prices.observed_at` is the live-spot timestamp):

```sql
select min(price_date) as earliest, max(price_date) as latest, count(*) as rows
from aurum_daily_closes;
```

```
earliest    | latest     | rows
2021-09-20  | 2026-09-18 | 1258
```

The claimed 2021-04-14 / 1 January 2000 values are no longer in the product. The
calculator already derives everything from the history the page loads — there are
no date literals in `src/components/aurum-calculator-section.tsx` or
`src/lib/aurum/price-state.ts`. Rendered values measured in the browser:

```
date input min = 2021-09-21
date input max = 2026-09-18
helper text    = "Any date from 21 September 2021 onward."
                 "AURUM stores the last five years of daily closes, so the
                  earliest available date moves forward each day."
```

(The served history starts one day after the stored minimum because the public
endpoint returns a rolling five-year window from the latest close.)

## 4. Admin sign-in with email + password

### Auth configuration

- Email/password sign-in enabled.
- **Self sign-up disabled at the auth server** (`disable_signup = true`), plus
  breached-password rejection (`password_hibp_enabled = true`). Anonymous users
  stay off; auto-confirm stays off.
- No public sign-up form exists anywhere in the app.

### Server boundary — `src/lib/admin-password.server.ts`

1. Rate-limit check first (by salted email hash **and** salted IP hash).
2. The email must already be on the `aurum_editors` allowlist — otherwise the
   attempt is recorded and the generic message returned, with no password check.
3. Password verified through the publishable client.
4. Defence in depth: the account that actually signed in is re-checked against
   the allowlist; if it is not listed, `auth.signOut()` runs immediately and the
   generic message is returned. No tokens leave the server in that case.
5. Only on success are the session tokens returned, and the browser calls
   `supabase.auth.setSession()` with them.

One generic message for both wrong email and wrong password:
`"That email and password do not match an account with access."`

### Password rules

- Minimum 12 characters, **no maximum**, no forced rotation.
- Top common passwords and single-character repeats rejected locally; the auth
  server additionally rejects breached passwords.

### Account creation

Only from **Admin → People**, by an admin, through `setEditorPassword`
(service role). The email must already be on the allowlist. The value is typed
by the admin into the app, sent once, handed to Supabase Auth, and cleared from
the form — never logged, returned, or written to any file. No first-admin
password was generated: existing admins bootstrap with the magic link and then
set their own password on the People page.

### Rate limiting

New table `public.aurum_admin_login_attempts` (migration
`0019_admin_login_attempts.sql`): RLS on with **no policies**, service_role
grants only, salted hashes only, indexed by email and IP, with a 7-day prune
function. 10 failures in 15 minutes on either bucket locks further attempts,
including ones with the correct password.

### Magic link

Kept as the "Forgotten password?" fallback on the sign-in screen.

### Tests — `src/lib/admin-password.server.test.ts` (10 passed)

- under 12 characters rejected; top common passwords rejected; long passphrase
  accepted with no maximum;
- weak password refused even for a listed account;
- password refused for an address not on the allowlist;
- **self sign-up blocked at the auth server**;
- allowlisted account signs in and receives tokens;
- correct password for a non-allowlisted account denied, no session returned;
- identical message for unknown email and wrong password;
- 10 failures then lock-out, refusing even the correct password.

All fixtures (editor row, auth users, attempt rows) are removed afterwards.

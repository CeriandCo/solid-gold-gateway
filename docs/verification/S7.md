## 4. Conclusion on the reported failure

`checkout_attempts` rows: 17:30:30, 17:31:12, 17:31:23, 17:31:52 (all `kind='checkout'`).
`gift_card_orders` shows sessions created at 17:31:13, 17:31:23 and 17:31:52 — i.e. every attempt
from 17:31:12 onwards produced a real Stripe Checkout Session. Only the 17:30:30 attempt wrote no
order, which given the code path means it got past the settings gate and was refused at the origin
check or at `S7_NO_PRICE` — consistent with the catalog price ids / fourth origin being written
between those two clicks. The condition is not reproducible now: every allowlisted origin, the
server runtime and the published site all complete checkout.

## 5. Data hygiene

Cause: the commerce suites insert into the real `gift_card_orders` and deliberately left rows behind
("purged by a manual verification step"), and `commerce-checkout.server.test.ts` cleaned up with
blanket deletes (`delete().not("attempt_id","is",null)` and `delete().neq("ip_hash","")`).

Fixes:
- Migration `0020_commerce_purge_test_order.sql`: `commerce_purge_test_order(uuid)` (SECURITY DEFINER,
  service_role only, refuses `livemode = true`) removes an order with its cards, ledger rows,
  delivery attempts and alerts. The append-only ledger trigger now yields only inside that function,
  via the transaction-local `commerce.allow_ledger_purge` flag.
- New `src/lib/commerce/test-orders.ts` (`trackTestOrder` / `purgeTrackedOrders`); the webhook,
  refunds and delivery suites track every order they insert and purge it in `afterAll`.
- `commerce-checkout.server.test.ts` now records the salted IP buckets it used and deletes only those
  orders and `checkout_attempts` rows — no blanket deletes.
- `gift-delivery.server.test.ts` no longer writes blank switches in teardown; it restores the
  operator's snapshot.

Deleted (via the new purge function, all `livemode = false`): 20 `gift_card_orders` rows — the 12
suite rows from 17:11–17:12 with `recipient-*@example.com` recipients (including the XSS probe
string) plus 8 open diagnostic orders from this task's probes — together with 12 `gift_cards`,
10 `gift_card_ledger` rows and 9 `gift_card_delivery_attempts`. `stripe_events` and `commerce_alerts`
were already empty.

After re-running all four suites, the tables are clean and settings are intact:

```
orders 0 | cards 0 | ledger 0 | delivery_attempts 0 | stripe_events 0
commerce_settings: true | usd | 4 origins
```

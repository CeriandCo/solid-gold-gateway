## 2. Defects found and fixed this phase

1. **Unit spelling mismatch.** The live tables store `unit = 'troy_ounce'`; the fact pack only
   accepted `oz|ozt|troy ounce`, so every real run skipped with
   `{"outcome":"skipped","reason":"unsupported_currency_or_unit","runId":"10eaabae-…"}`.
   Fixed in `src/lib/aurum/ai/fact-pack.ts` (spot **and** daily close now validate the same
   normalized unit predicate; the daily-close branch previously validated no unit at all).
2. **`persist` not wired.** `buildRunDeps` omitted `persist` and the `as RunDeps` cast hid it, so
   a real run failed with `{"outcome":"error","reason":"persist_failed: TypeError: deps.persist is
   not a function","runId":"deba7550-…"}`. Fixed in `src/lib/aurum/ai/cron.server.ts`; the cast was
   removed so the compiler enforces completeness, and a regression test asserts every dependency is
   present.
3. **Verifier rejection on a real draft.** First verified run returned
   `{"outcome":"rejected","reason":"subject_missing_in_text (paragraph 3)","runId":"b111db90-…"}` —
   correct fail-closed behaviour. The system prompt now states the word "gold" must appear in every
   fact paragraph. The verifier was not weakened.

## 8. Limitations / open items

- **Cadence is not enabled.** No schedule is active. To enable, set
  `AURUM_AI_DAILY_NOTES_ENABLED=true` (and optionally `AURUM_AI_MAX_RUNS_PER_DAY`, default cap
  applies) and point a scheduler at `POST /api/public/aurum-ai-daily-note` with the
  `x-cron-secret` header. This requires the client's cadence decision.
- **Public byline unresolved.** No person is named; posts carry system provenance only.
- Model output is not deterministic: a run can legitimately end `rejected` when a draft breaks a
  safety rule (observed once, see §2.3). That is the intended fail-closed behaviour, not an error.
